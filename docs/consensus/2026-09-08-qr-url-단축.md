# QR URL 단축 방식 결정

> 상태: **미해결 (0/1)**

## 문제

`DownloadQr` 가 QR 에 담는 건 GCS V4 서명 URL 이다. RSA-SHA256 서명이라 **700~850자**로
고정이고 줄일 수 없다. 이걸 QR 로 만들면:

- 모듈 120~130개 (QR 버전 25~29) — "점이 너무 많아 징그럽다" (사용자, 2026-09-08)
- 320px 표시 기준 모듈 하나가 2.5px 남짓 — jsQR 디코딩은 되지만 폰 스캔 여유가 빠듯
- 가운데 로고를 얹으면 ECL 을 Q 로 올려야 해서 더 빽빽

`qr-code-styling` 교체·로고 삽입·크기 키우기는 이미 반영(2026-09-08). 근본 해결은 **QR 에
짧은 URL 을 담는 것**뿐이다.

## 제약 — IAP

우리 Cloud Run 서비스는 **IAP 가 엣지에서 전체를 덮는다** (경로별 예외 불가). 부스 방문자는
`@mz.co.kr` 로그인이 없으므로 **우리 도메인의 어떤 URL 도 못 연다.** 그래서 지금도
`storage.googleapis.com` 직행 서명 URL 을 쓰는 것. 짧은 URL 도 이 벽을 넘어야 한다.

## 선택지

### A. 리다이렉트 전용 2번째 서비스 (IAP 없음) — 추천

- 새 초경량 Cloud Run 서비스(또는 2세대 Cloud Function) `smprojects-dl`. IAP 안 검.
- 업로드 시 `gs://smproject-sh/links/<6자>.txt` 에 실제 오브젝트 경로만 기록.
- `GET https://<dl-host>/<6자>` → txt 읽기 → V4 서명 URL 생성 → `302` redirect.
- QR 에 담기는 URL: `https://<dl-host>/a7f3k9` — **~35자, 모듈 ~30개(버전 3)**. 확 성겨짐.
- 서명은 그대로 유지(오브젝트 비공개). 런타임 SA 에 서명 권한 이미 있음.
- 비용: min-instance 0, 트래픽 미미 → 사실상 0.
- **커스텀 도메인·LB 불필요.** 이 서비스가 받는 기본 `*.run.app` URL(~50자)이면 QR 모듈 ~40개로
  충분히 성기다. 도메인은 나중에 생기면 그때 매핑.
- 작업: `server/` 에 리다이렉트 핸들러 1개 + 배포 타깃 1개 추가. 사용자가 콘솔에서
  서비스 생성(IAP 미적용) + URL 확인. `DL_BASE_URL` 을 메인 앱 env 에 주입.
- 단점: 배포 대상이 2개가 된다.

### B. GCS 객체 공개 읽기 + 짧은 랜덤 이름

- 업로드 시 이름을 `output/<8자>.png`, 객체에 `allUsers:objectViewer`.
- QR: `https://storage.googleapis.com/smproject-sh/output/a7f3k9m2.png` — **~62자, 모듈 ~55개(버전 8)**.
  A 보다는 길지만 지금(130)보다 훨씬 나음.
- 서명·TTL 없음. 행사 후 스태프 수동 삭제(이미 합의 D6)와 잘 맞음.
- 작업: `tryon.ts`·`omni.ts` 업로드부에 `makePublic()` + 이름 규칙. 새 서비스 없음.
- 단점: 행사 기간 동안 생성물이 **인터넷에 공개**된다 (이름을 모르면 접근 불가하지만
  "비공개"는 아님). **동의 팝업 문구에 "임시 공개 링크로 제공" 추가 필요.**

### D. 외부 HTTPS 로드밸런서 + 커스텀 도메인 + 경로별 IAP

- LB 를 앞에 두고 URL 맵으로 경로 분기: `/`·`/api/*`·스튜디오 라우트 → IAP **적용**,
  `/d/*` → IAP **미적용**(공개). 리다이렉트 핸들러는 지금 앱에 라우트로 추가.
- 짧은 커스텀 도메인: `https://sm.<도메인>/d/a7f3k9` — **~30자, 모듈 ~30개**. A 와 동급.
- 한 도메인·한 서비스로 정리됨. 나중 데모에도 재활용.
- **비용:** 외부 HTTPS LB 포워딩 규칙이 시간당 과금(~$0.025/hr ≈ $0.6/일, 상시 유지 시 월 ~$18)
  \+ 요청 과금. 부스 기간만 켜면 소액이지만 0 은 아니다. (A·B 는 사실상 0)
- **작업량:** 포워딩 규칙 + 타깃 프록시 + URL 맵 + 백엔드 서비스 + serverless NEG +
  관리형 SSL 인증서(DNS 검증, 발급까지 15~60분) + **IAP 를 Cloud Run 에서 LB 백엔드로 이전** +
  Cloud Run ingress 를 "내부/LB 만" 으로 제한. 콘솔 클릭이 많고, IAP 이전은 잘못하면
  전체 잠김/노출 위험.
- **선행 조건:** 커스텀 도메인 보유 + DNS 위임 권한 (`mz.co.kr` 서브도메인이면 사내 IT).
- CLAUDE.md 의 기존 결정("Cloud Run 에 IAP 직접, LB 불필요")을 뒤집는 것.
- **판단:** 방식 자체는 가장 "정석"이지만, 부스까지 6일 남은 시점에 QR 미관 개선 하나를 위해
  비용·리스크·작업량이 크다. B 는 코드 1시간 + 인프라 0 으로 미관의 90%를 얻는다.

### C. 외부 단축 API (is.gd·TinyURL) — 비추천

- QR: `https://is.gd/xxxxx` — ~20자, 가장 깔끔.
- 단점: 서명 URL(SA 이메일 포함)이 제3자에 로깅 / 서명 1시간 만료 → 곧 죽은 링크 /
  부스에서 외부 API 의존 / "GCP 네이티브 우선" 과 어긋남.
